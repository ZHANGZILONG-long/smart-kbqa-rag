## 一、项目三句话（背熟）

1. 我用 **Django + DRF + JWT** 做了一个企业知识库问答系统。
2. 文档上传后用 **Celery 异步**解析分块，向量存 **Chroma**，问答用 **LangGraph 多步 RAG** 接 **DeepSeek**。
3. 做了 **三种角色权限**、部门文档隔离、上传审批、多轮对话记忆，以及限流、审计、Docker 部署。

---

## 二、六个核心概念（每个一句话）

| 概念 | 一句话解释 |
|------|-----------|
| **RAG** | 先检索相关片段，再让大模型基于片段回答，减少幻觉、可溯源 |
| **JWT** | 登录发 access（短）+ refresh（长），access 过期用 refresh 换 |
| **RBAC** | 总管理员 / 部门管理员 / 普通员工，三种角色能力不同 |
| **Celery** | 耗时的文档解析丢给后台 worker，不堵住 HTTP 请求 |
| **向量检索** | 把文字变成一串数字（向量），语义相近的就能被搜到 |
| **对话记忆** | 最近几轮原文进上下文，更早的压成摘要，总长度有预算 |

## 三、权限矩阵（画在白板上就能讲）

| | 上传 | 审批 | 管员工 | 看审计 |
|---|---|---|---|---|
| 总管理员 | ✅ 直接入库 | ✅ | 全员 | ✅ |
| 部门管理员 | ✅ 待审批 | ❌ | 仅本部门普通员工 | ❌ |
| 普通员工 | ❌ | ❌ | ❌ | ❌ |

**所有人看文档的范围**：全员可见 + 本部门已入库；自己上传的待审批文档自己能看到。

## 四、三条链路（能画出来就够）

### 1. 登录
```
POST /api/auth/login/ → 返回 access + refresh → 前端存起来
之后每个请求带 Authorization: Bearer <access>
```

### 2. 文档入库
```
上传 → 部门管理员的状态是「待审批」（不进向量库）
     → 总管审批通过 → 状态变待处理
     → Celery 任务：抽文本 → 分块 → 转向量 → 存 Chroma → 状态就绪
     → 失败重试 3 次，最后标记失败并告警
```

### 3. 问答
```
用户提问 → 带上最近几轮对话，改写问题（把「它」补全成完整查询）
        → 按权限检索向量库 → 判断够不够
        → 不够就再检索一次 → 够了就让大模型生成回答 → 返回答案 + 来源
        → 落库后异步把滑出窗口的旧对话压成摘要，下一轮提问时用
```

**记忆三层**（一句一层）：

| 层 | 内容 | 为什么 |
|----|------|--------|
| 短期 | 最近 6 轮原文 | 追问能接上 |
| 长期 | 更早对话的滚动摘要 | 关键信息不丢 |
| 预算 | 历史最多 4000 字，单条最多 800 字 | 别把本轮检索到的资料挤掉 |

## 五、必答 12 题（一句话答案）

| # | 问题 | 答案要点 |
|---|------|---------|
| 1 | 三种角色分别能干什么？ | 见上面权限矩阵 |
| 2 | 权限为什么要过滤两次？ | 列表走数据库、问答走向量库，只做一处会泄露 |
| 3 | 部门文档为什么要审批？ | 防止未审内容被检索到，合规要求 |
| 4 | 为什么用异步处理文档？ | 解析+向量化很慢，堵住请求会超时 |
| 5 | 任务失败了怎么办？ | 重试 3 次，最终标记失败，可选 webhook 告警 |
| 6 | RAG 流程有几步？ | 改写 → 检索 → 评分 → (不够再检索) → 生成 |
| 7 | 怎么减少幻觉？ | 只根据检索内容回答 + 评分判断 + 返回来源可核对 |
| 8 | JWT 怎么退出登录？ | refresh 加入黑名单，access 短命自然过期 |
| 9 | 问答为什么要限流？ | 每次调用都花大模型的钱，不限会被刷爆 |
| 10 | 备份要备什么？ | MySQL、media（上传文件）、chroma（向量库）；漏了向量库检索就废了 |
| 11 | 多轮对话的记忆怎么做的？ | 最近 6 轮原文 + 更早的滚动摘要 + 字符预算；历史只帮理解，不提供事实 |
| 12 | 删除会话和清空记忆有什么区别？ | 删除会话连消息一起级联删（`DELETE /api/qa/sessions/<id>/`），不可恢复；清空记忆只清摘要和上下文、消息保留。两者都写审计 |

## 六、每天 10 分钟怎么练（最重要）

**不要读代码。要「说出来」。**

1. 拿一张白纸，画三条链路（登录 / 入库 / 问答）
2. 合上纸，出声讲一遍，手机录下来
3. 回放录音，卡住的地方就是没懂的地方，去查那一个文件
4. 一周后重复，你会发现越讲越顺

**判断标准**：你能给一个完全不懂技术的朋友讲明白「文档怎么变成能问答的知识」，就算过关了。

---

## 七、可以主动说的不足（显得诚实、有判断力）

- 权限到「部门」级，没到单个文档级别
- 流式输出是先算完再推送，不是大模型逐字真流式
- 向量库用的 Chroma，数据量大要换成专业方案
- 监控只做了日志和健康检查，没接 Prometheus
- 记忆只到会话级，没有跨会话的用户级记忆；摘要有损，细节会丢

---

## 八、如果只记一个东西

**记这条数据流**：

```
上传 PDF → Celery 异步 → 切块 → 变向量 → 存 Chroma
                                            ↓
你提问 → 带上最近几轮对话 → 权限过滤 → 检索相关块 → 大模型生成 → 带来源的回答
```

这一条串起了整个项目。能讲清它，面试就够用了。
